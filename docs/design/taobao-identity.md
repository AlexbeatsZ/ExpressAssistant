# 淘宝取件身份码

## 范围与会话

2026-11-16 用户确认0.9.15可正常使用，追加要求支持淘宝的取件身份码，部分场所不能使用菜鸟身份码。本需求与包裹的取件码无关。

身份码页面同时显示两张卡片，上方菜鸟、下方淘宝；每张卡片独立显示平台标题、条形码、码文本和刷新按钮，不再切换平台。菜鸟继续使用原有会员会话、在线码与离线材料；淘宝使用设置中已登录、已启用的淘宝账号。多淘宝账号时可选择账号并记住选择。登录、获取旧会话等操作仍放设置，不加入身份码页面。

## 官方接口与证据

- 参考开源项目 yimeifun/PickTool 的 Destination、xianhe51920/handycode 的 UrlPolicy，它们指向官方页面：`https://pages-fast.m.taobao.com/wow/z/uniapp/1011717/last-mile-fe/end-collect-platform/identity-code`。
- 直接检查官方页面加载的 `last-mile-fe/end-collect-platform/1.0.426/js/p_identity-code-index.js` 和 `main.js`：取码 API 为 `mtop.cainiao.pickup.identity.getIdentityMessage` 1.0，普通入口参数 `stationType=XN`。请求上下文为 miniappSrc=ST、productType=YZ、固定asac和页面sourceUrl。沿用淘宝H5登录态及H5签名，不借用菜鸟会员会话。
- H5网关SUCCESS响应的 `data.data.identityCode` 是实际码。官方请求封装也允许 `data.result`，解析只读取身份码字段；姓名、手机号和其他数据不保存、不显示、不记录。
- 2026-11-16 本人淘宝会话先已过期，订单与两个身份接口均返回SESSION_EXPIRED；用户通过设置重新登录后，新接口SUCCESS并返回20字符、XNS前缀的实际码。同一会话调用旧nbpickup.identitycode.get仍仅返回五个false，不能当成该用户未认证或没有淘宝码。
- 不修改或伪造服务端码，不把菜鸟CS8码替换前缀后展示成淘宝码。

## 刷新与失败

- 官方页面轮询周期为180000ms。本版按此周期前台刷新，并将已取得的淘宝码限制在本次三分钟展示窗口内；这个本地展示窗口不声称是服务端明确保证的有效期。按用户自用界面要求，两张卡片统一只显示MM:SS纯时间，不加「后自动刷新」等字样。
- 没有可验证的离线材料，因此不本地生成淘宝码，也不跨进程持久化实际码；联网失败时只保留本次窗口内的已有码，窗口结束即停止展示。
- 会话过期立即隐藏该淘宝码，明确要求在设置重新登录，停止自动重试；网络等失败至少间隔一分钟重试。用户主动刷新仍可重试。
- 真实接口紧接着重复取码曾返回pickup-4002「条形码重复，请刷新重试」，按固定不可用错误处理，不高频重试；未到本地刷新窗口的已有码仍可显示。
- H5轮换Cookie成功后更新同一个淘宝账号；若请求期间用户换号、停用或重新登录，该旧请求结果不能覆盖新会话。
- 切换淘宝账号、页面隐藏会取消对应界面请求，并以代次屏蔽迟到结果。两种码的状态、错误、账号和刷新相互独立，禁止用另一平台码兜底。
