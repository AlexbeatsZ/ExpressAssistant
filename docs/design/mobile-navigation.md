# 手机导航与搜索

## 2026-11-04 用户要求

- 手机是纯快递工具，移除内置对话、模型配置、语音、记忆、AI 进度/ETA、商品 AI 短名和日报；服务器只提供确定的查询/操作接口给外部工具，不在软件内接入模型。
- 固定底部栏，左「快递」、右「身份码」，切换留在同一页面壳内。快递页顶部搜索，输入运单号自动识别承运商，在搜索结果处直接添加；不再独立弹出添加页。
- 页面不出现验收状态、材料续期策略、项目模块说明等开发信息。身份码页只显示码和刷新操作；导入与维护用 API。
- GitHub、支持和更新统一指向 AlexbeatsZ/ExpressAssistant。保留开源许可中的上游署名。

## 视觉和交互

2026-11-06 用户追加要求：手机只保留莫奈取色，删除主题入口、温暖纸感与自定义配置。配色使用 Material 系统动态取色，昼夜跟随系统；字体为系统无衬线，码与单号保留等宽，条形码保留白底。升级时仅清理旧主题偏好，不重置其他数据；详见 `docs/THEME.md`。

```
快递                         日历 清单 设置
[ 搜索商品、快递公司或运单号            × ]
[ 承运商 · 运单号                  添加 ]  ← 仅识别到新运单号时出现
快递列表 / 搜索结果 / 空状态
─────────────────────────────────────
          快递            身份码
```

身份码使用同一工具栏和底部栏；内容只放白底条形码、码文本、刷新按钮、必要的操作错误。未出码给「暂不可用」和重试动作，不解释材料实现。底部栏避开系统手势区；键盘打开时保持搜索可用。

2026-11-16 追加淘宝身份码：按用户最新要求同时展示两张身份码卡片，上菜鸟、下淘宝，各自独立刷新；多个已启用淘宝账号时在淘宝卡片显示账号选择。两种码各自显示自身错误，淘宝无有效码时不回退到菜鸟码；登录仍在设置。淘宝码前台按官方三分钟周期自动刷新，显示下次刷新倒计时。

2026-11-16 用户修正入口：身份码页移除所有登录获取、Root 说明和打开菜鸟操作；设置「账号与同步 → 菜鸟登录」默认使用包内 SDK 登录。旧获取方式仅作为设置中的可选连接方式，通知也返回该设置页。刷新按钮的图标和文字按整体居中、保持单行。单包与登录约束见 `cainiao-embedded.md`、`cainiao-login.md`。

识别使用本地运单格式初筛与已有承运商识别接口，输入停顿后查询。只在点击「添加」或提交键盘搜索时保存新件，避免输入未完成时创建多个包裹。相同运单号不重复添加；命中已完成记录时可直接打开。

普通关键字过滤商品名、单号、公司、取件码；搜索包含已完成和异常记录。空查询恢复当前快递分区。手动件有独立 manual 来源，跨渠道同步保留，详情走通用查件接口。

维护入口：MainActivity 接受 query 预填搜索、mailNo 打开已有记录、identity_code 打开身份 tab，供已授权 ADB 与小组件导航，不另装测试组件，也不把私有 DetailActivity 改成导出。输入预填仍走同一搜索监听和承运商识别逻辑。

2026-11-05：已完成入口使用已有 ic_checklist，24dp图标居中于48×48dp触摸区；沿用工具栏主题色和反馈，保留btn_done及无障碍说明/长按提示“已完成”。

2026-11-09：搜索提示改为“搜索商品 / 粘贴运单号添加”；单号允许粘贴含空白的文本，提交仍需明确添加。查重同时比较 mailNo 与 trackingNumber，避免把已关联 PDD 的真实运单再建为手动件。家人订单可按单号创建 manual 记录，不要求绑定该购物账号。普通同步刷新手动件；需要收件信息验证的查询仍受接口实际要求限制，本轮没有替用户填写家人的验证信息。

## 短信、剪贴板与输入框导入（2026-11-14）

- 三个入口统一使用 WaybillRules。新运单为 12～17 位 ASCII 字母、数字和半角短横线，至少 6 个数字、最多 6 个非数字，并保留 `6位数字-10位以上数字` 的拼多多订单号排除条件。输入框保持既有空白归一化，普通关键字仍用于本地筛选；格式失败时承运商识别、运单详情请求和新件写入均不执行。
- 剪贴板在 App 从后台回到前台且窗口获得焦点后读取，包含身份码、设置等已打开页面的前台恢复；App 内页面跳转不重复读取。读取全部完整字符段并逐项校验，避免截断超长串，多件去重后自动添加。识别结果沿现有 manual 记录及菜鸟优先、快递100回退查询流程补全。剪贴板关闭开关位于设置的自动导入页。
- 短信依赖 Android READ_SMS / RECEIVE_SMS 运行时授权。首次启动会提出系统授权请求，拒绝后可在自动导入设置重新开启或跳转应用权限。首次授权扫描已有收件箱，此后按短信 `_id` 游标增量扫描；每次前台恢复补漏，新短信广播可在后台排队导入，多段短信合并识别。关闭开关后停止导入，重新开启继续补漏。
- 短信要求正文有快递或派件语境。URL 中的编号以及明确标为订单号、交易号、验证码、取件码、手机号和电话的字段排除。短信正文和完整剪贴板内容只用于内存解析，持久化数据仅包括匹配运单、配置和扫描游标。
- 自动导入按 mailNo / trackingNumber 查重，尊重用户已删除的快递，防止旧短信和剪贴板恢复隐藏记录。显式输入框添加继续允许恢复。Store 锁内再次判断已有及隐藏记录，平台同步通过既有 retainManualEdits 保留并发导入。
- 本地写入后用唯一 WorkManager 任务查询轨迹，等待联网并在异常时重试，避免切到后台取消 Activity 协程而中断导入。主页监听 Store 变更就地刷新。既有短单号历史记录仍可打开和刷新，新添加执行新规则。
